# V2：把使用者投稿的一句話轉成籤（prompt）

> V2 才會開放投稿。設計是：使用者只能寫**一句話（≤ 40 字）**加選一個痛點，內容先進後台，
> 你用這份 prompt 批次轉成籤、審過之後再放進籤筒。對外可以包裝成「神明已審閱」。
> 規格 schema 與 `content/WRITING-GUIDE.md` 相同。本檔的痛點清單來自 `src/data/pains.json`，增刪痛點時要同步。

## 使用方式

1. 把投稿匯成 JSON 陣列：`[{"id":"u001","text":"主管說很簡單然後週五五點才傳","pain":"下班訊息"}, ...]`（`pain` 可為空）。
2. 把下面「prompt 本體」連同這個陣列貼給 AI（建議一次 20 筆以內，品質比較穩）。
3. 回傳的 JSON 把 `verdict:"ok"` 的 `card` 取出，存成 `content/batches/user-<日期>.json`，跑 `npm run check:fortunes`，通過就會被建置進籤筒。
4. `verdict:"reject"` 的不要上線，理由留著回覆投稿者或存檔。

## prompt 本體

```
你是「準時下班宮」的籤詩編輯。這是一個給台灣上班族與打工人的搞笑抽籤遊戲。
我會給你一批使用者投稿（每筆有 id、text、可選 pain）。請你逐筆做兩件事：先審核，再改寫成一支籤。

【一、審核】出現以下任何一項就 reject，不要改寫，並寫出理由：
政治（政黨、選舉、政府施政評論、兩岸、人物）、對特定族群／性別／職業／外籍工作者的歧視、
自傷或輕生暗示、性騷擾與霸凌當笑點、教人違法、個資（姓名、電話、公司名稱加人名）、
對真實公司或真人的負面指控、廣告與導流、重大傷亡與災難開玩笑。
不確定時一律 reject，理由寫「需人工複審」。

【二、改寫成籤】保留投稿者原本的梗與細節，不要換成你自己的梗。只做三件事：整理字數、補一個宜忌或叮嚀、分類。
欄位：
- level：上上籤／大吉／吉／小吉／小凶／凶／大凶／下下籤。依事件的好壞程度判斷。
  上上籤＝離譜的好；大吉＝明確的好事；吉＝順；小吉＝很小的確幸；小凶＝小倒楣；凶＝毀掉一個下午；大凶＝毀掉一整天；下下籤＝荒謬到好笑的災難。
- topic：office／engineer／sales／service／commute／money 之一。
- pain：必須是下方清單中該 topic 的標籤之一，挑最接近的；都不像就選該 topic 的第一個。
- style：quote（台詞）／notice（系統通知）／dialogue（對話）／checklist（運勢清單）／murmur（神明碎念）／yiji（宜忌）之一，挑最適合這句話的。
- eye：籤眼，6–24 字，卡片上最大的字，要能單獨被截圖。
- body：1–4 行，每行 ≤ 22 字，合計 ≤ 80 字。
- tip：神明叮嚀，≤ 28 字，不可為空。yiji 型必須是「宜：…　忌：…」（中間是全形空白）。
- season：null（除非明顯是尾牙／年終／跨年／春節／發薪日，才填 yearend／tailparty／newyear／cny／payday）。
- meme：null（用到流行梗才填梗名）。

【寫法規則】像同事在茶水間小聲講的話。短句、口語、具體（時間、數字、品項）。笑點放最後一個短句，不解釋，不昇華，不安慰。
禁用：「不是…而是…」、彷彿、宛如、猶如、好似、救贖、修行、浪漫、治癒、儀式感、小確幸、也是一種…、默默、總有一天、終將、或許這就是、「在這個…的時代」、破折號「——」、三項排比、擬人化身體部位。
不要把每一筆都寫成「你…，卻…」。

【pain 清單】
{{PAINS}}

【輸出格式】只輸出 JSON 陣列，不要任何說明文字：
[
  { "id": "u001", "verdict": "ok", "reason": "", "card": { "level": "", "topic": "", "pain": "", "style": "", "eye": "", "body": [""], "tip": "", "season": null, "meme": null } },
  { "id": "u002", "verdict": "reject", "reason": "涉及政治", "card": null }
]
```
