# 籤詩寫作規範 v1

寫之前讀完。寫完跑 `npm run check:fortunes`，紅字一定要改。

## 1. 檔案格式

每個批次一個 JSON 檔，放在 `content/batches/<批次名>.json`，內容是陣列：

```json
[
  {
    "level": "大凶",
    "topic": "office",
    "pain": "下班訊息",
    "style": "quote",
    "eye": "「這個很簡單，下週一要。」",
    "body": ["— 週五 17:55・主管", "簡單的定義，由不用做的人決定。"],
    "tip": "宜：手機沒電　忌：回「收到」",
    "season": null,
    "meme": null
  }
]
```

| 欄位 | 規則 |
|---|---|
| level | 上上籤／大吉／吉／小吉／小凶／凶／大凶／下下籤 |
| topic | office／engineer／sales／service／commute／money |
| pain | **必須**是 `src/data/pains.json` 裡該 topic 的 label 之一 |
| style | quote／notice／dialogue／checklist／murmur／yiji |
| eye | 籤眼，卡片上最大的字。6–24 字。 |
| body | 1–4 行，每行 ≤ 22 字，合計 ≤ 80 字 |
| tip | 神明叮嚀，≤ 28 字。每張都要有。 |
| season | null，或 yearend／tailparty／newyear／cny／payday |
| expires | null，或 YYYY-MM-DD。時事梗填「還會熱到哪一天」，過了那天自動不再出現。常青籤填 null |
| meme | null，或這張用到的流行梗名稱（方便之後下架過期的梗） |

`id`、籤號由 `npm run build:fortunes` 自動產生，不要自己寫。

## 2. 六種籤型

| style | eye | body | 範例 |
|---|---|---|---|
| quote 台詞 | 一句引號台詞 | 第 1 行：時間・誰說的；第 2 行：吐槽 | 見上方 JSON |
| notice 系統通知 | 【系統通知】開頭的一句 | 1–2 行神明補充 | 【系統通知】你的特休 3 天已被「專案需要」取代。／神明補充：這不是駁回，這是「暫緩批准」。 |
| dialogue 對話 | 最痛的那一句 | 2–4 行對話，用「主管：」「你：」「（內心）」分行 | 主管：明天你不用進來／（你的心跳漏一拍）／主管：颱風假，在家休息 |
| checklist 運勢清單 | 一句總評 | 4 行，每行「項目 ★★☆☆☆」，最後一行可加括號吐槽 | 加薪 ☆☆☆☆☆／摸魚 ★★★☆☆／開會 ★☆☆☆☆／準時下班 ★★★★☆ |
| murmur 神明碎念 | 神明自言自語 | 1–2 行補充 | 神明翻了你的紀錄，嘆了一口氣：「又是你。」 |
| yiji 宜忌 | 一句情境 | 1–2 行 | tip 用「宜：…　忌：…」 |

**notice 型不要全用同一個殼**：標頭輪流用【系統通知】【公告】【提醒】【帳單】【群組】【薪資單】【班表】【客服】【請款通知】等，【系統通知】最多 70%。第一行補充不要都寫「神明補充：」（上限 40%），可以改成「備註：」「小字：」「下面還有一行：」，或直接是一句話。murmur 型的主詞不要都是「神明」，輪流用香爐、籤筒、廟公、土地公、金身、供桌、籤詩本人。eye 以「今日運勢／今日總評」開頭最多 10%。

目標占比：quote 20%、notice 16%、dialogue 16%、checklist 14%、murmur 16%、yiji 18%。
tip 不是每張都寫宜忌。只有 yiji 型和約 30% 其他型用宜忌，其餘用一句叮嚀或加碼吐槽。

## 3. 等級調性

| 等級 | 調性 |
|---|---|
| 上上籤 | 離譜的好，好到不敢相信。要有「這不可能是真的」的荒謬感 |
| 大吉 | 明確的好事，一件大事順利 |
| 吉 | 順，剛好，沒出包 |
| 小吉 | 很小的確幸，小到只有上班族懂 |
| 小凶 | 小倒楣，苦笑一下就過 |
| 凶 | 明顯的麻煩，一個下午被毀掉 |
| 大凶 | 一整天毀掉，連續兩個打擊 |
| 下下籤 | 荒謬到好笑的災難。要有笑點，不能只是慘 |

等級之間的差距要看得出來。小凶和下下籤放在一起，讀者要一眼分得出。

## 4. 怎麼寫才像人寫的

- 像同事在茶水間小聲講的，不像文案。句子短，口語。
- **具體**：有時間（17:58）、數字（37 封）、品項（滷肉飯）、檔名（final_v7）、金額（多 800 元）。至少 60% 的卡要有。
- **笑點放最後一個短句**，不解釋笑點，不補一句昇華。
- 「你」不要每張都出現（整批 ≤ 40%）。多用主管、客戶、群組、系統、印表機當主詞。
- 可以直接引用人說的話。至少 40% 的卡要有「」引述或對話。
- 台灣用語：欸、啦、喔、吧、靠。不要堆疊，也不要全用書面語。
- 吉籤是「鬆一口氣」或「不敢相信」的幽默，不是雞湯。凶籤要有一個 punch，不是純粹的慘。
- 梗要用得自然，不要硬塞。2026 的流行梗整批 ≤ 15%，並填 `meme` 欄位。

## 5. 禁用

**句型（checker 會抓）**：
「不是…而是…」、「彷彿／宛如／猶如／好似」、「一種救贖／修行／浪漫」、「也是一種…」、「默默」、「小確幸」、「儀式感」、「治癒」、「總有一天」、「終將」、「或許這就是」、「在這個…的時代」、「讓你…」（整批 ≤ 10%）、破折號「——」、省略號堆疊。
比喻（像／如同／好比／等於）整批 ≤ 20%，單張最多 1 個。
擬人化身體部位（「你的腰也表示感謝」這種）禁用。
「A 不改需求，但願意替你改 B」這類工整對仗禁用。

**結構**：
- 不要每張都是「你…，卻…」。轉折詞「卻」整批 ≤ 8%，「終於」「突然」各 ≤ 3%。
- 不要三項排比。不要「先…再…最後…」。
- 不要把兩句寫得一樣長、一樣節奏。

**內容**：
- 政治（政黨、選舉、兩岸、政府施政批評）、宗教攻擊、地域／族群／性別／外籍工作者歧視。
- 自傷、輕生、重大災害與傷亡、職災開玩笑。
- 對真實公司或真人的負面指控（品牌名可以當中性場景，例如「7-11 的咖啡」）。
- 性騷擾、霸凌當笑點。
- 教人違法（逃稅、偷竊、竄改紀錄）。

## 6. 時令與時事

- 時令籤填 `season`：yearend 考績年終、tailparty 尾牙、newyear 跨年元旦、cny 春節、payday 發薪日。
- 時事梗必須中性、跟上班族日常有關（物價、連假、搶票、手搖飲聯名、AI 取代工作這類）。**不碰政治。**
- 要用語料檔 `reference/ai-response-01.md` 裡的內容時，只取主題與場景，用自己的話重寫，不要照抄句子。
- 該檔「為何有共鳴」欄的句式帶有 AI 味，不能當範本。
